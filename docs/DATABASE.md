## 3. Money, currency, fiscal fields
- `*_cents` columns are **bigint minor units of the row's `currency`** (UZS: tiyin, 1 so'm = 100). No DB default currency; it comes from `markets.currency` (`UZ`/`UZS` seeded).
- `products.ikpu_code` (IKPU/MXIK): `^(DEMO-)?[0-9]{17}$`, required to publish (`products_published_requires_ikpu`). `package_code` nullable. `vat_rate_bp` int NOT NULL 0..10000, **no default** (0005): every product insert must set it explicitly (seeds write 1200 = 12 %).
- **DEMO IKPU**: seed products use `DEMO-` + 17 digits. Generated column `ikpu_is_demo` exists on `products` and `order_items`. **Payments must refuse to issue a live fiscal receipt or take a live payment for any line with `ikpu_is_demo = true` (or `ikpuCode` starting `DEMO-`).**
- `order_items` snapshots `ikpu_code`, `package_code`, `vat_rate_bp` at convert time (from the checkout snapshot line `ikpuCode/packageCode/vatRateBp` if present, else from `products`).
- `products.slug <> 'facets'` (reserved path).

## 4. Function contracts (for Payments & Orders)
All in `public`, `SECURITY DEFINER`, `SET search_path = ''`, EXECUTE **service_role only** (also callable by the owner role behind `DATABASE_URL`). TS wrappers: `src/server/inventory/reservations.ts` (`inventory.reserve/convert/convertWith/release/releaseExpired/adjust/restockOrder`, errors mapped to `ApiError`).

Errors are `RAISE EXCEPTION '<CODE>' USING ERRCODE = 'P0001', DETAIL = <json>`; read `err.message` for the code and `err.detail` for JSON:
| Code | DETAIL | HTTP mapping |
|---|---|---|
| `OUT_OF_STOCK` | json array of variant ids (ALL failing lines: unknown, inactive, unpublished, short) | 409, `details.variantIds` |
| `PRICE_CHANGED` | json array of variant ids (snapshot `unitPriceMinor` ≠ current price) | 409, `details.variantIds` |
| `IDEMPOTENCY_CONFLICT` | `{"checkout_id"}` — same idempotencyKey, different payload hash | 409 `IDEMPOTENCY_CONFLICT` (wrapper throws `ApiError.idempotencyConflict()`) |
| `VALIDATION_ERROR` | `{"field": ...}` | 400 |
| `NOT_FOUND` | `{"checkout_id"|"variant_id"|"order_id": ...}` | 404 |
| `INVALID_STATE` | `{"checkout_status"|"reason": ...}` | 409/400 |
| `AMOUNT_MISMATCH` | `{"expected_minor","expected_currency","got_minor","got_currency"}` | reject callback (Payme -31001) |
| `INSUFFICIENT_STOCK` | `{"variant_id"}` (adjust would go below reserved) | 400 |

### `reserve_checkout(p_checkout_id uuid, p_items jsonb, p_expires_at timestamptz, p_payload_hash text default null) returns void`
- Precondition: the app has inserted the `checkouts` row (status `open`/`awaiting_payment`) with `items` = `CheckoutSnapshotLine[]` (camelCase: `variantId, sku, productName, size, colour, unitPriceMinor, quantity, lineTotalMinor, ikpuCode, packageCode, vatRateBp`), `subtotal_cents = Σ unitPriceMinor·quantity`, `total_cents = subtotal + shipping + tax − discount` (CHECK), `access_token_hash` (B1, lower-case hex `HMAC_SHA256(ORDER_TOKEN_SECRET, token)`, computed by Payments), `provider`, `expires_at` = provider session expiry (now + 30 min).
- `p_items = [{"variant_id": uuid, "quantity": 1..10}]`, no duplicates, must equal the snapshot lines (else `VALIDATION_ERROR`).
- Locks variants `ORDER BY id`, re-checks: variant active, product published/not archived/`published_at <= now()`, product currency = checkout currency, snapshot price = DB price (`PRICE_CHANGED`), stock (`OUT_OF_STOCK`). Then `stock_reserved += q` (spec §4 conditional UPDATE) and inserts `stock_reservations` (expires_at = `p_expires_at`, use now + 35 min), sets `checkouts.reserved_until = p_expires_at`.
- **Idempotent**: calling again for the same checkout with the same lines while reservations are active is a no-op.
- **`idempotencyKey`** (contract `createCheckoutRequest.idempotencyKey`): `checkouts.idempotency_key uuid UNIQUE NULL` + `idempotency_payload_hash` (lower-case hex **HMAC-SHA256(ORDER_TOKEN_SECRET, canonical request payload)**, computed by Payments — not plain sha256, so a stored hash cannot be used to confirm a guessed email/address; required when the key is set; the Architect's docs sometimes call it `idempotency_request_hash` — the canonical DB column name is `idempotency_payload_hash`). Race-safe pattern in ONE transaction: `INSERT INTO checkouts (..., idempotency_key, idempotency_payload_hash) ... ON CONFLICT (idempotency_key) DO NOTHING;` → `checkout_id_for_idempotency_key(key, hash)` (returns the id; raises `IDEMPOTENCY_CONFLICT` if the stored hash differs → API 409) → `reserve_checkout(id, items, expires, hash)` (no-op on repeat; also checks the hash) → return the existing checkout. Tested with 10 parallel submits (1 checkout, 1 reservation) + a different-payload submit (IDEMPOTENCY_CONFLICT). TS: `inventory.checkoutIdForIdempotencyKey()`, `inventory.reserveWith(…, { payloadHash })`.
- Guest token: the createCheckout response carries `guestToken`/`accessToken` once; the DB never stores it, only `access_token_hash` (HMAC hex, see below).

### `convert_checkout_to_order(p_checkout_id uuid, p_order jsonb, p_conflict_mode text default 'record') returns jsonb`
`p_conflict_mode` ∈ `record` | `abort` (contract `conflictMode`; anything else → `VALIDATION_ERROR`).
- `p_order = {"reference"?: "DY-YYYYMMDD-XXXXX" (generated if absent), "provider", "provider_payment_id", "amount_minor", "currency", "paid_at"?, "raw"?}`.
- Returns `{"order_id","reference","status":"paid"|"stock_conflict"|"already_converted"|"aborted","order_status","conflict_variant_ids":[...]}` (`aborted`: order_id/reference null).
- Locks checkout → its reservations → variants (id order) before writing (no deadlocks under parallel webhooks). Verifies provider and **amount + currency = checkout total** (`AMOUNT_MISMATCH`, nothing written).
- All reservations of THIS checkout `active` → order `paid`: `stock_on_hand -= q`, `stock_reserved -= q`, `inventory_movements(reason 'sale', order_id)`, reservations `converted`, `payments` row `succeeded`, `order_events(payment_received)`, checkout `completed`, `orders.access_token_hash` copied from the checkout.
- Any reservation not active (released/expired by cron) → `record`: order `stock_conflict`, **no stock change**, `payments` succeeded (refund it), `order_events(stock_conflict)`; `abort`: **writes nothing** and returns `status:'aborted'` + `conflict_variant_ids` (no exception; the caller's transaction stays usable; Payme/Click Perform after expiry → provider error).
- `order_items.vat_rate_bp` = snapshot `vatRateBp`, else `products.vat_rate_bp` (NOT NULL, no default) — no hardcoded 12 % anywhere.
- Second call → `already_converted`, nothing changes. A `provider_payment_id` already used for another order → `INVALID_STATE`.

### `release_checkout(p_checkout_id uuid, p_reason text) returns int`
`p_reason ∈ expired | payment_failed | canceled`. Releases active reservations (`stock_reserved -= q`, status `released`, `released_at`), checkout → `expired` (or `failed`) if still open/awaiting_payment. Returns reservations released; 0 on repeat.

### `release_expired_reservations(p_now timestamptz default now(), p_limit int default 500) returns int`
Cron fallback: releases active reservations with `expires_at <= p_now` per checkout (`FOR UPDATE SKIP LOCKED`), checkouts → `expired`. Returns reservations released. Cron flow (contract): provider `cancel(session)` → `release_checkout(..., 'expired')`; this sweep catches stragglers.

### `adjust_stock(p_variant_id uuid, p_delta int, p_reason inventory_movement_reason, p_note text, p_actor_id uuid) returns int`
`p_delta ≠ 0`, |delta| ≤ 10000; reason ≠ `sale`; `p_actor_id` may be NULL (system). Never below `stock_reserved` (`INSUFFICIENT_STOCK`). Writes the movement. Returns new `stock_on_hand`. New variants start at 0 stock; initial stock = `adjust_stock(…, 'restock')`.

### `restock_order(p_order_id uuid, p_reason inventory_movement_reason default 'return', p_actor_id uuid default null, p_note text default null) returns int`
Return path, e.g. **Payme CancelTransaction after PerformTransaction**: puts back exactly what this order's `sale` movements took (minus earlier restocks), movement reason `return`/`cancellation`, `order_events(stock_restocked)`. Idempotent; a `stock_conflict` order restocks 0. Does not change order status (transitions.ts does).

### `record_payment_event(p_provider payment_provider, p_event_id text, p_type text, p_payload jsonb default null) returns boolean`
`true` = first delivery (process it), `false` = duplicate (answer 200/provider-specific OK). `mark_payment_event_processed(p_provider, p_event_id, p_error text default null) returns void` sets `processed_at`/`error`.

### `provider_transactions` (B18)
Table for Payme/Click transactions (`ProviderTransaction` in `src/contracts/payments.ts`): `provider, provider_txn_id` UNIQUE, `checkout_id` NOT NULL, `order_id` NULL until Perform/Complete, `state` enum `created|performed|canceled|canceled_after_perform`, `amount_cents`, `currency`, `cancel_reason int`, `seq bigint` (identity, monotonic → per-provider monotonic; never insert it; Payme GetStatement ORDER BY seq), `provider_time bigint` (provider's ms timestamp, e.g. Payme `time`; nullable; GetStatement filters `provider_time BETWEEN from AND to`), `raw jsonb`, `created_at/performed_at/canceled_at/updated_at`.

`refunds.idempotency_key` is **text** NOT NULL UNIQUE (1..200 chars) since 0005, e.g. `admin:<uuid>` or a provider-derived key. Server only (service_role / owner); Payments reads/writes it directly (`INSERT ... ON CONFLICT (provider, provider_txn_id) DO NOTHING` for CreateTransaction idempotency).

### Guest order token
DB stores only `access_token_hash` = lower-case hex of `HMAC_SHA256(ORDER_TOKEN_SECRET, token)`, computed by Payments when the token is minted at checkout (B1); the DB never sees the token or the secret and only enforces the format (`CHECK ~ '^[0-9a-f]{64}$'`, 0005). Test fixtures use any 64-hex value. Lookup is a server query: `... where reference = $1 and access_token_hash = $hash` (unknown or wrong → 404).

## 5. RLS matrix
RLS is ON for every public table. "server" = only `service_role` / `DATABASE_URL` (bypass RLS); no anon/authenticated grants or policies at all.
| Table(s) | anon | authenticated (customer) | editor | fulfilment | owner |

| products, product_translations, product_images | published only | published only | all + write | all (read) | all + write |
| product_variants | active of published; columns WITHOUT `stock_on_hand/stock_reserved` (only `in_stock`) | same | read all + write non-stock columns | read | same as editor |
| categories (+translations) | active | active | all + write | all (read) | all + write |
| size_charts, tags | all | all | write | read | write |
| articles (+translations, article_products, article_tags) | `published/scheduled` with `published_at <= now()` | same | all + write | public only | all + write |
| markets, countries, shipping_methods, shipping_rates | active / shippable | same | read | read | all + write |
| profiles | — | own row read; update `full_name` only | read all | read all | read all |
| admin_users | — | own row read; **cannot insert** (QA-03) | own row | own row | all + write |
| checkouts, orders, order_items, order_events, payments, refunds, shipments, payment_events, provider_transactions, stock_reservations, inventory_movements, audit_log, newsletter_subscribers | — | — | — | — (server APIs) | — (server APIs) |
| storage `product-images` | public URL download only (no listing, 0007) | same | list + upload/update/delete | public URL only | list + upload/update/delete |
Admin = `app_private.is_admin(roles)` (SECURITY DEFINER, reads `admin_users` by `auth.uid()`, `is_active`; owner always passes). Fulfilment work (orders, shipments, stock adjust) goes through server routes that check the role. Inactive admins are treated as customers. Stock columns cannot be written directly by anon/authenticated/service_role (column grants); `inventory_movements` UPDATE/DELETE/TRUNCATE revoked + trigger.

Public read helpers (all `security_invoker = on` / SECURITY INVOKER, so RLS + column grants apply):
- `storefront_products` (+`category_slug`, `price_from_cents`, `available`), `storefront_variants` (`price_cents` effective, `available`, `ikpu_code`, `package_code`, `vat_rate_bp`, `size_system`), `storefront_articles`.

- `product_facets(p_category_slug text default null) → jsonb` matching `catalog.productFacetsResponse.data` (`sizes[{value,label,count,sizeSystem}]`, `colours[{value,label,count,hex}]`, `priceMinor{min,max,currency}|null`), only published products with an active in-stock variant. Route: `GET /api/v1/products/facets`.
- Exact stock is never exposed: availability uses the generated column `in_stock = stock_on_hand - stock_reserved > 0`, which is the only stock column granted to API roles (instead of a definer function, so no SECURITY DEFINER function is callable by anon).

## 8. Public API (Backend-owned routes, `src/app/api/v1/**`)
All public reads run in a READ ONLY transaction with `SET LOCAL ROLE anon` (`asAnon()` in `src/server/db/client.ts`), so RLS, the
column grants (no stock counts) and the `security_invoker` views apply exactly as for a browser anon key. Handlers:
`parse(contract) → service (src/server/catalog|journal) → respond(contract)`; responses are validated against the Zod contract.
| Route | Service | Notes |
|---|---|---|
| `GET /products` | `catalog/products.ts` | filters category (incl. sub-categories), size, colour (case-insensitive, active variant), min/maxPrice on price-from; sort new/price_asc/price_desc; opaque keyset cursor |
| `GET /products/{slug}` | `catalog/products.ts` | 404 for unknown/draft/archived/future; variants expose only `available`; fiscal fields not exposed |
| `GET /products/facets` | `catalog/facets.ts` | `product_facets()`; sizes in natural order (XS<S<M<L, numeric) |
| `GET /categories` | `catalog/categories.ts` | active tree; name/description fall back to `en`, then slug |
| `GET /search` | `catalog/search.ts` | prefix tsquery built from letters/digits only (no tsquery injection); products + articles, rank-merged |
| `GET /articles`, `GET /articles/{slug}` | `journal/articles.ts` | published + `published_at <= now()`; tags; shoppable products; keyset cursor |
| `POST /cart/validate` | `catalog/cart.ts` | public facts as anon; stock facts computed by the server role **as booleans inside SQL** (`in_stock`, enough-for-requested-qty, `lowStock` = sellable ≤ 3) — no count ever leaves the DB. Quantities 1..`MAX_LINE_QTY` (10) per contract. Over-stock request keeps its quantity and gets `insufficient_stock` (never clamped). Issues `out_of_stock / insufficient_stock / inactive / unpublished / not_found`. Residual: a client can binary-search the count by repeating requests with different quantities (≤ 10) — accepted trade-off (same as any shop's "only N left" UX). |
| `GET /shipping/options` | `catalog/shipping-options.ts` | 422 `COUNTRY_NOT_SHIPPABLE`; rate tier by `subtotalMinor` hint; price 0 when hint ≥ freeOver |
| `POST /newsletter`, `GET /newsletter/confirm` | `journal/newsletter.ts` | always 202; honeypot + per-IP (10/10 min) and per-email (3/h) in-memory limits; upsert is idempotent; confirm token stored as sha256 hex, 7-day TTL. **Confirmation email not sent yet** (hook `onToken` for Payments' email module) |
Integration test: `src/server/db/tests/api_smoke.sh` (82 curl checks incl. 400/404/422) against `next dev` + a local DB from `apply-local.sh`.
Env for the routes: `DATABASE_URL` (server), `NEXT_PUBLIC_SUPABASE_URL` (image URLs), plus whatever `serverEnv()` requires.
